# Artifact formats and schemas

The checked-in `schemas/` directory is generated from the Rust types:

```bash
termtrace schemas --out schemas
```

Tests require generated bytes to match the checked-in files, validate every schema against the JSON Schema meta-schema, and validate recording/replay fixtures against their schemas.

## Canonical

- `session.json`: canonically serialized immutable command, initial geometry, geometry source, optional capture viewport and Ghostty-fit hash, optional canonical Ghostty-profile provenance and focused overrides, sensitivity-aware environment inventory under an explicit provenance policy, build provenance, and the selected output durability policy. It is durably published before the event log.
- `ghostty-config.txt`: flattened, hashed effective Ghostty configuration when fitted geometry or a visual-profile option was requested. Recursive config-file controls are removed so capture does not depend on the original source file.
- `events.jsonl`: header (including the exact `session.json` BLAKE3, effective Ghostty defaults, and palette) followed by ordered, BLAKE3-chained event records. Raw bytes are standard padded Base64.
- `requests.jsonl`: an auxiliary hash-chained mutation-outcome journal. Each record binds a request UUID and command hash to operation IDs, the canonical event range and terminal hash, and the exact response returned to the caller.
- `completion.json`: format and validation versions, session-manifest and event-header hashes, exit, output count, event count, terminal event sequence, final event hash, configured durability policy, observed maximum uncommitted bytes/time, sync count, and final-sync result.

Only these files describe execution truth. Inputs, resizes, and signals use intent/result pairs. A missing result means uncertain delivery, not failure and not permission to retry. Input intents retain exact bytes plus a structured raw, text, semantic-key, or paste descriptor. Key descriptors include modifiers and the pinned encoder identity. Key and paste descriptors bind the live terminal-mode snapshot used for encoding; paste also records whether bracketed wrappers were applied.

Sessions created through `start NAME` retain `creation_alias` as immutable invocation context. It is never substituted for the session ID, manifest hash, or canonical path in evidence relationships; later registry retargeting cannot rewrite it.

A restart successor adds `lineage` to its immutable manifest. The object records `reason: "restart"`, the predecessor session ID, BLAKE3 of the exact predecessor `session.json`, and the predecessor's final event hash from validated completion. Ordinary recordings use `null`. This binds generations without making mutable aliases part of canonical identity.

Environment inventory entries distinguish `value`, `hash`, `name`, and `not_captured`. Value capture includes exact bytes plus BLAKE3; hash capture supports equality checks when a candidate value is available but does not make execution reproducible. Custom variable names are classified as potentially sensitive unless they belong to the conventional terminal/locale/timezone set.

Execution provenance also records the requested and resolved executable paths, recorder binary/build and semantic-engine revisions, real/effective UID and GID, privileged identity state, process umask when exposed by the host, and runtime kernel identity. File content identity is explicit as `not_requested`, `captured`, `unresolved`, or `unavailable`. Reproducible policy hashes complete executable and recorder files plus a direct script argument for recognized interpreters; it does not scan arbitrary arguments and guess which files influenced execution.

Control responses carry separate durable and observed event/hash/output boundaries. Read-only control traffic is not an event and cannot change the canonical hash. A marker is the explicit operation for placing an observation in the execution timeline.

`Observation` is the shared state-view envelope for CLI and client layers. It labels source kind, canonical session identity and completion, requested `StatePoint`, state/event/time identity, presentation eligibility, validated or observed boundary, capture quality, semantic/native truth layer, compact frame, and frame hash. Plain-text rendering may emit only `frame.viewport_text`; structured output retains the complete envelope.

`requests.jsonl` supports persistent idempotency after bounded memory-cache eviction. It is not a canonical evidence root: readers may discard and reconstruct retry state from canonical events, and `termtrace verify` reports a missing, verified, or invalid journal without allowing journal damage to invalidate an otherwise complete event chain.

A completed session must end in `Exit` and contain no pending mutation intent. Run `termtrace verify SESSION --level content --json` for a stable offline report, or use `--level durability-record` to additionally require the internally consistent chain-bound persistence record. Offline verification cannot prove that historical sync calls reached stable media. A valid unsigned hash graph establishes integrity relative to the roots in the session; it does not authenticate who created them.

`evidence-receipt.json` is an optional detached envelope. Its unsigned payload binds the session ID, manifest hash, final event hash/count, exact completion hash, and an artifact-root count/head checkpoint. The exact signed bytes are the ASCII domain prefix `TERMTRACE-EVIDENCE-RECEIPT-V1` plus a NUL byte and compact Serde JSON of the fixed-order typed payload. The signature is excluded from the payload and uses the `termtrace-evidence` OpenSSH namespace. Receipt creation time comes from the signing host's system clock and is not an external timestamp.

`verify --level signature` first performs complete content verification, then checks payload roots and detached cryptography. It reports `signature_cryptographic_valid`, `signature_signer_trusted`, and `session_authenticity_established` independently. Trust requires a caller-owned OpenSSH allowed-signers file. Artifact authenticity is true only when a trusted receipt covers the complete currently verified artifact-root catalog.

Named-session registry entries are mutable convenience metadata outside canonical evidence. Each owner-only `registry/NAME.json` binds a validated alias to exact canonical path bytes, the immutable session ID, control-protocol version, publication time, and optional recorder PID/process-start pair. Resolution reopens the manifest and rejects path or identity substitution. Registering an alias never modifies the session and never replaces an existing binding.

Registry listings classify entries as `live`, `completed`, `incomplete`, `stale`, `missing_evidence`, `identity_mismatch`, or `incompatible`. Live registration derives the PID from socket peer credentials and pairs it with `/proc/PID/stat` start ticks; listing never trusts a PID alone. The default listing contains only live entries, while `--all` retains unhealthy rows and their focused diagnostics. Alias removal unlinks and directory-syncs only the registry entry.

Live commands use one positional session-reference grammar. A value containing `/` or beginning with `.` is a path; any other value is a registry name. `path:` and `name:` force either interpretation, including a relative single-component path. The former preserves non-UTF-8 path bytes; registry names are restricted to the versioned ASCII alias grammar.

## Semantic derived

- `derived/states.jsonl.zst`: Zstandard-compressed JSONL distinct state deltas.
- `derived/state-index.jsonl`: compact event/time/hash mappings.
- `derived/final.txt`, `final.vt`, `final.html`: pinned Ghostty formatter output.
- `derived/manifest.json`: source and engine provenance plus the relative path, exact length, whole-file BLAKE3, media/schema type, sensitivity, and relationship of every payload member.

Ranged indexes have the same files under `derived-range-FROM_NS-TO_NS/`. Their manifest `source_range` is a non-empty half-open interval with inclusive `start_monotonic_ns` and exclusive `end_monotonic_ns`; full-session manifests use `null`. `source_complete` proves whether `completion.json` matched the indexed log. Explicit live snapshots are hash-addressed and remain ineligible for native capture. Presented-only indexes use `derived-presented…/`, record `state_selection: "presented"`, and retain both artifact and complete semantic state counts.

## Native visual derived

- `visual/session.mkv`: lossless RGB H.264 at 24 FPS.
- `visual/final.png`: direct X11 final frame.
- `visual/video-map.jsonl`: semantic state to approximate frame mapping.
- `visual/manifest.json`: config hash, versions, launch overrides, clocks, parent-side geometry report, and media probes.
- component logs and resolved `ghostty-config.txt`.

Native manifests apply the same whole-file member contract, including media, maps, configuration, and diagnostic logs. Symlinks, devices, non-normalized paths, duplicate members, altered members, and files added after manifest construction fail verification.

Ranged captures use `visual-range-FROM_NS-TO_NS/`. Their manifest repeats the exact `source_range`, and video-map timestamps stay on the absolute canonical timeline even though frame calculations are relative to range start. Full-session captures retain `visual/` and a `null` source range.

Completed derivations are appended to the separately locked and synchronized `artifact-roots.jsonl` hash chain. Each root binds the exact manifest, session-manifest hash, source event hash, derivation identity/type, and relative directory. Post-processing never appends to the closed canonical event log. `termtrace verify` checks member self-consistency, source binding, and local catalog order. The local unsigned catalog is not authentication; `artifact_authenticity_established` remains false unless a later trusted detached checkpoint proves it.

All session and derived files are owner-only. Schema validity does not imply trust: terminal content is untrusted and potentially sensitive.
